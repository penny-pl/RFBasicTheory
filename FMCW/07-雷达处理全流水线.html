雷达处理全流水线

ADC → 2D-FFT → 去杂波 → CFAR → 角度 FFT → 点云 → 目标列表 —— 一帧数据的完整旅程

一、理论要点

1. 全链路总览

ADC → 距离FFT → 去静态杂波 → 多普勒FFT → CFAR → 角度FFT → 点云 → 聚类/跟踪 → 目标列表
每一级都在回答一个问题：能量在哪个距离、哪个速度、哪个角度；最后由跟踪层回答"这是谁、它要去哪"。

2. ADC 与数据立方体

一帧原始数据是三维张量：采样点 N × chirp 数 M × 天线 K（复数 I/Q）。
本仿真 512×64×8 = 26 万复样本 ≈ 1 MB/帧（IQ16bit）。芯片内部用硬件流水线实时消化，对外只吐点云。

3. 2D-FFT：尺寸不变、能量浓缩

距离维 512→256 个有效 bin，速度维 64 chirp→64 个速度 bin，天线维保留。数据量没少，但目标能量从"摊满全帧"浓缩到几个 RD 单元，噪底不变——SNR 陡增几千倍，这是后面一切检测的资本。

4. 去静态杂波

对每个 (距离bin, 天线) 沿 chirp 求均值再减去：v=0 的分量（护栏、静止车辆、TX 泄漏的直流）集中在均值里被整体扣除。
⚠ 静止目标同归于尽。停车场模式里 v=0 的大 RCS 车辆开了去杂波就"消失"——自己试试。

5. CFAR：图 → 点

在 256×64 的 RD 功率图上做二维滑窗恒虚警（本仿真：保护 2、训练 6、Pfa=10⁻⁴），输出若干 (距离bin, 速度bin) 坐标。一帧最多几十个点——数据量从 26 万骤降到几十。

6. 角度 FFT：点 → 方向

对每个检测点，取 8 个虚拟天线在该 (距离,速度) 单元上的复数向量做空间 FFT，谱峰即方位角。至此一个检测点升级为 (R, v, θ) 三坐标，投影成笛卡尔点云：x=R·sinθ，y=R·cosθ。

7. 聚类与跟踪：点云 → 目标

一个真实车辆往往散成多个点（角反射体多）。DBSCAN 按密度把邻近点聚成团；GHT（几何直方图）识别"团"的形状类别；Kalman/UKF 跟踪跨帧关联同一目标、平滑抖动、外推遮挡时刻，最终输出带 ID 的目标列表：位置/速度/角度/尺寸/置信度。

8. 四个典型工程问题

① 近距直流与 TX 泄漏：bin0 被污染，靠近 0 m 有盲区；
② ghost 目标：多径（护栏二次反射）出现镜像假点；
③ 弱目标遮蔽：强目标抬高 CFAR 门限压死邻近弱目标；
④ 点云抖动：单帧估计噪声使点跳来跳去——靠跟踪滤波平滑，这也是"点云≠目标列表"的原因。

二、仿真：mini 雷达模拟器（完整流水线）

三、小结与常见误区

要点回顾：① 一帧 = N×M×K 数据立方体；② 2D-FFT 把能量浓缩进 RD 单元（SNR 增益数千倍）；③ 去杂波删 v=0 一切；④ CFAR 把图变成几十个 (R,v) 点；⑤ 角度 FFT 补上 θ，投影为点云；⑥ 聚类+跟踪把点云变成带 ID 的目标列表；⑦ 工程四大坑：泄漏、ghost、遮蔽、抖动。
误区："点云就是雷达的输出。"点云只是中间产物：单帧点云有抖动、有假点（多径/副瓣）、一个车可能是一把点。真正的产品输出是跟踪后的目标列表——位置速度都经过滤波、有 ID、能预测。把点云直接喂给下游是新手最常见的错误。
误区："流水线各级独立，可以各自调到最优。"级与级强耦合：去杂波激进 → CFAR 少吃假点但行人危险；CFAR 门限低 → 点云变密 → 聚类参数又得变。工程调参的顺序是从前往后：先把波形与杂波抑制理顺，再动 CFAR，最后调跟踪，反过来调会顾此失彼。
误区："目标没检出就是 CFAR 参数不对。"先查上游：目标可能落在 Rmax/vmax 之外（不模糊范围）、被去杂波删掉（v≈0）、或 RCS 太小 SNR 不足。CFAR 只能在"图上有的东西"里挑——图上没有的，怎么调都检不出来。
