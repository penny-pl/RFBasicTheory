chirp 参数设计

带宽→分辨率 · 斜率×采样率→最大距离 · 周期→最大速度 · 数量→帧率 —— 四个旋钮的联动与折中

一、理论要点

1. 四个旋钮

波形由 B（扫频带宽）、Tc（chirp 周期）、N（每帧 chirp 数）、fs（ADC 采样率）完全决定，斜率 S=B/Tc 是派生量。
芯片（如 TI AWR 系列）的可配项就是这四个量。设计波形 = 在互相打架的约束里找一组可行解。

2. 约束链一：B → 距离分辨率

ΔR = c / 2B
500 MHz → 30 cm；1 GHz → 15 cm；4 GHz → 3.75 cm。只与带宽有关，其他参数动不了它。法规：76~77 GHz 与 77~81 GHz（4 GHz）两个窗口。

3. 约束链二：S×fs → 最大距离

Rmax = fs·c / (4S) = fs·c·Tc / (4B)
拍频上限 fs/2 卡住远距离：想看得远，要么降斜率（拉长 Tc），要么提采样率。而 ADC 采样率受芯片限制（典型 ≤ 25~45 MS/s）。

4. 约束链三：Tc → 最大速度

vmax = ±λ/(4Tc)
想覆盖高速公路 ±40 m/s，Tc ≤ 25 µs（77 GHz）——chirp 必须又短又快。但短 chirp 配大带宽意味着陡斜率，又反过来压缩 Rmax。

5. 约束链四：N·Tc → 速度分辨率与帧率

Δv = λ/(2·N·Tc)　　T帧 = N·Tc
N 加倍 → Δv 细一倍，但帧时间加倍。车载要求 50~100 ms 一帧（对应跟踪刷新 10~20 Hz），限制了 N·Tc 的上限。

6. 数据率：躲不开的洪水

每帧原始数据 ≈ (fs·Tc)采样点 × N chirp × K 接收通道 × 4 字节（IQ16bit）。LRR 量级约 1 MB/帧/通道，上百帧/秒就是每秒上百 MB——所以 2D-FFT 必须在芯片内硬件流水线实时完成，对外只输出点云，而不是原始数据。

7. 经典矛盾："又要远、又要快"

远 → 低斜率 → 长 Tc；快（大 vmax）→ 短 Tc。两个需求顶牛：
vmax·Rmax = fs·λ·c/(16·B)
B 和 fs 固定后乘积是常数！工程解法：长短 chirp 交替（远帧+快帧轮流发）、MIMO 分时复用，或者干脆分雷达分工（LRR 专远、角雷达专快）。

8. 三类典型波形（TI AWR 量级）

LRR 长距：B≈300~500 MHz、Tc≈40~45 µs、N=256、fs≈25 MS/s → ΔR≈0.4 m、Rmax≈200 m、±23 m/s；
SRR 短距：B≈4 GHz、Tc≈85 µs、N=64 → ΔR≈3.7 cm、Rmax≈40 m；
角雷达：B≈1 GHz、Tc≈25 µs → 大视场大 vmax、Rmax≈30 m。

二、仿真 ①：交互波形设计器

四个滑块联动计算全部指标，指标卡按当前预设的目标打红黄绿：绿=达标、黄=贴线（5% 余量内）、红=不达标。先点预设看一组"教科书解"，再随便拧一个滑块切到自定义，体会牵一发动全身——尤其试试把 Tc 拉短看 vmax 上去而 Rmax 掉下来。

三、仿真 ②：帧结构时频图

把当前参数画成时间-频率图：一帧 = 连续 N 个锯齿 chirp。注意这只是开头几段的示意——LRR 一帧有 256 个锯齿、SRR 有 64 个。斜率越陡（黄线），同样距离拍频越高、Rmax 越小。

四、小结与常见误区

要点回顾：① B→ΔR；② S·fs→Rmax；③ Tc→vmax；④ N·Tc→Δv 与帧率；⑤ vmax·Rmax 在 B、fs 固定时是常数——远与快天生顶牛；⑥ 原始数据每秒上百 MB，2D-FFT 必须片上硬件实时做；⑦ 三类雷达（LRR/SRR/角）各拿自己最在乎的指标。
误区："带宽越大越好。"4 GHz 带宽（77~81 GHz）确实给 3.75 cm 分辨率，但斜率被迫陡峭（除非 Tc 拉长），Rmax 掉到几十米——这就是 SRR 只做近距离的原因。带宽是要用最大距离换的。
误区："N 加到 512，速度分辨率 0.09 m/s 多精确。"N·Tc 加倍意味着帧时间加倍：25 ms 变 50 ms，跟踪刷新掉到 20 Hz，高速目标在两帧间跑 2 米——"看得细"变成了"跟不上"。分辨率要够用就好。
误区："采样率提高总没错。"fs 只需要 ≥ 2×最远目标拍频。再高只是白吃数据率、功耗和存储带宽（每秒多出几十 MB 的洪水），对分辨率毫无贡献——分辨率在带宽 B 手里。
延伸阅读：《FMCW 测距原理》——ΔR 与 Rmax 公式的来龙去脉；《多普勒测速与 RD 图》——vmax、Δv 的物理来源；《雷达处理全流水线》——这帧数据接下来怎么被吃掉。
